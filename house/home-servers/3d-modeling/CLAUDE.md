### 🎯 ПРАВИЛО СКРУГЛЕНЬ від користувача (2026-07-03 v2, ЗАКОН для всіх стиків)
**Скруглення ЗОВНІШНЄ (roundover зовнішнього ребра) → ОПУКЛИЙ профіль;
скруглення ВНУТРІШНЄ (у внутрішньому куті) → УВІГНУТИЙ профіль (ков).
Переходи мають «перетікати», не «перескакувати».** (Перша редакція через
кути >90/≤90 не покривала всі випадки — користувач переформулював.)
Приклади: плече вертикаль↔нахил — опуклий R5 БЕЗ піка; задній кут профілю —
опуклий R5; стик рейл↔бортик, кінці брови — впадини.

### Уроки OCC цієї сесії (2026-07-03)
- **Fuse мовчки викидає солід** після булевого вирізу на філетованому тілі
  (right-стінка зникала з union). Фікс: `.fix()` на результаті вирізу.
- **3D-філет на смузі з приклеєними коробками** лишає вироджену грань (null
  triangulation → діри STL, .fix() НЕ лікує). Фікс: без 3D-філетів — профіль
  з R2 у 2D + чверть-револьви для кутів.
- **Дотичні поверхні (ков↔площина)** = T-стики в STL; лікується «жирним»
  перекриттям (клапоть 0.5мм поверх).
- **Ков-стрічки (_cove_prism): профіль ВТОПЛЮВАТИ на 0.3 у кут** — кінці
  чверть-дуги дотичні до граней; лінія дотику по всій довжині (напр. Z7 на
  стінці) дає нон-маніфолдні ребра STL (злиплі трикутники), fill_holes
  безсилий. Втоплений профіль виходить із грані трансверсально → чисто.
  Дотичні бутт-мітри стрічок між собою — теж утоплювати (cove5 −0.6 у плінтус).
- **Справжній sweep неможливий**, коли радіуси поворотів шляху < глибини
  профілю (самоперетин) — псевдо-свіп: band-екструзія + standalone-філет.
- **Сплайс файлу по index()** при переставлених функціях створює ДУБЛІКАТИ
  визначень (виграє останнє = старе) — перевіряти grep-ом кількість def.

## ⚙️ КЛЮЧОВІ УРОКИ
- **Візуалізація для звірки — це критично.** Скатер-плоти й вершинні «карти висот» користувач читає погано.
  Найнадійніше: **власний top-down растеризатор із z-буфером** (`/home/claude/topdown.py`, функція `rasterize`)
  — дає чистий рендер згори, як у CAD-в'юері. Косий растеризатор `/home/claude/oblique.py` шумить (стінки-спайки).
- **Найкращий канал звірки — сам користувач у своєму CAD-в'юері.** Він відкриває STL і анотує скріни.
- **Точні координати:** користувач ставить **FreeCAD** (стиль навігації CAD для миші / Gesture для тачпада)
  або **MeshLab (PickPoints)** і дає XYZ прямо в моїй системі координат (STL 1:1). Так різати ТОЧНО, без здогадів.
- **Павутину** робити як **різницю** (region − union(cell.buffer(−1))), не через boundary.buffer (заливає нутро).
- **Соти = суцільне − шестикутні отвори, POINTY-TOP** (кути 30..330); flat-top → «зірки Давида».
- **extrude_polygon** павутини буває не watertight → merge_vertices/nondegenerate_faces/fill_holes/fix_normals.
- **Свіп валика** — власна `sweep()` (кільця профілю вздовж плоского шляху; внутрішня нормаль = праворуч руху).
- Після union лишати найбільше тіло (max volume); перевіряти watertight + bodies==1 перед present_files.
- **Не різати валик прямокутним boolean-боксом** наскрізь по Z — псує дно. Кінець свіпу = потрібний Y.
- **Filesystem MCP** може зависати ~4 хв на читанні; лікується повним перезапуском Claude Desktop.

## 🔀 РІШЕННЯ 2026-07-02: МІГРАЦІЯ НА ПАРАМЕТРИЧНИЙ CAD (build123d) + Claude Code

**Причина:** редагування оригінального меша = боротьба з чужою тріангуляцією (T-тріщини, buffer-роздуви,
«заокруглення не всюди», некрасиві стики старої/нової геометрії). Рішення користувача: нова модель
повністю НАША, параметрична, з STEP-експортом для FreeCAD.

**Інструмент: build123d 0.11 (OCCT-ядро, як у FreeCAD).** Перевірено в sandbox 2026-07-02:
ставиться (`pip install build123d --break-system-packages`), збірка 2-4 с, `export_step` + `export_stl`.
Тест: `b123d_test.step/stl` (кут дно+стінка+бортик+стояк з філетами) — користувач відкрив STEP у
FreeCAD, підтвердив.

### Уроки build123d/OCCT (важливо — здобуті кров'ю, 8 ітерацій)
- **Філети вимогливі до топології й ПОРЯДКУ.** Робочий порядок у тесті: вертикальні філети →
  верхні петлі (згори донизу). Галтель дна першою → тоді вертикальні падають (упираються в неї), і навпаки.
- **Вертикальні радіуси закладати у 2D-контур** (fillet вершин ескізу до extrude), а не 3D-філетом.
  3D-філети — лише на горизонтальні дотично-неперервні ланцюги (верхні петлі, галтелі).
- **Довгі гладкі елементи (валик)** — профільним свіпом (у OCCT рідний sweep), не філетами.
- **НЕ зливати тіла з копланарними гранями** — після цього філети масово падають (RuntimeError
  навіть у max_fillet). Перекриття робити «жирними» або стики точними butt-joint.
- **Баг build123d 0.11:** `fillet` вершин 2D-ескізу після union ескізів може падати
  (`Fillet algorithm failed for Vertex(...)` з координатами поза моделлю). Обхід: радіуси в кожному
  контурі ДО union, або 3D-філет вертикального ребра після extrude.
- **STL з OCCT не watertight «з коробки»** (грані тесселюються незалежно): після export_stl зшивати
  trimesh-ом: `merge_vertices(digits_vertex=4)` + nondegenerate + за потреби fill_holes. STEP — первинний
  формат, STL — похідний для друку.
- `max_fillet()` ненадійний (сам кидає RuntimeError) — не покладатись, підбирати радіуси свідомо.
